# NetSwitcher — Windows 网络配置快速切换

调路由器时反复改本机 IP 太烦，就写了这个。双击打开，选网卡，填地址，点应用。

**原生 WinForms，零第三方依赖。** 系统自带 .NET Framework 4.x 直接跑，不需要装任何东西。

## 两个语言版本

同一个程序，**编译出两个独立 exe**：

| | 中文版 | 英文版 |
|---|---|---|
| 文件 | `NetSwitcher-chs.exe` | `NetSwitcher-en.exe` |
| 界面语言 | 中文 | English |
| 命令行长文本 | 中文 | English |
| 客户区宽度 | 660 | **720** |
| 「关于」 | 中英对照 | 中英对照（不变） |

**为什么是两个 exe，而不是程序里加语言切换**：英文标签明显比中文宽（`Gateway` 57px vs 网关 32px、`Subnet Mask` 84px vs 子网掩码 56px），硬塞进中文那套列宽会把精心对齐的列网格顶坏。与其做一套两边都将就的布局，不如各给各的宽度。

**但源码只有一份**（`NetSwitcher.cs`），靠编译开关切换：

```bat
:: 中文版
csc ... /out:NetSwitcher-chs.exe NetSwitcher.cs

:: 英文版（多一个 /define:EN）
csc ... /define:EN /out:NetSwitcher-en.exe NetSwitcher.cs
```

所以**改一处 bug，两边一起修好**，不会走岔。

界面文字集中在文件里的 `L` 表（173 条，中英各一行）：

```csharp
A("f.gateway", "网关", "Gateway");
A("f.mask",    "子网掩码", "Subnet Mask");
```

改文案就改这张表。**万一 key 拼错，界面会显示 `<key名>` 而不是静默出错**，`--uidump` 一扫就能发现。

### 三个特色功能

**① 一键开关 IPv6**

IPv6 分组左下角那个按钮，文字跟着当前状态变：显示「关闭 IPv6」就是在开着，点一下关掉；变成「开启 IPv6」再点就开回来。

等价于在网卡属性里勾选/取消勾选「Internet 协议版本 6 (TCP/IPv6)」，**只影响这一块网卡，不需要重启**。

**② IPv4 和 IPv6 各自独立的 DNS**

IPv4 分组的 DNS 1 / DNS 2 只接受 IPv4 地址，IPv6 分组的只接受 IPv6 地址。填错了会当场报错，不会写进去。

**③ DNS 预设下拉**

两个分组各有一个「预设」下拉。**第一项固定是「恢复自动获取」，而且就是默认选中项** —— 选它会把上面两个 DNS 输入框清空，**并且应用时执行 `netsh ... set dnsservers source=dhcp`，把这一族 DNS 改回从上级路由器自动获取**（等价于网卡属性里的「自动获得 DNS 服务器地址」）。

选其它项则把该厂商的主/备 DNS 自动填进上面两个框（**注意：只是填进输入框，点「应用配置」才真正写下去**）。

于是两族 DNS 各有三种结果：

| 输入框 | 预设选择 | 点「应用配置」后的效果 |
|---|---|---|
| 有地址 | 任意 | 写入你填的静态 DNS |
| 空 | 恢复自动获取 | 改回从上级路由器自动获取 |
| 空 | 某个厂商 | 什么都不做（说明你选完预设又手工清了框）|

**这一条能单独用**：什么都不填、预设保持默认的「恢复自动获取」，直接点「应用配置」，就会把两族 DNS 都改回自动。改之前照样先存快照，所以「还原上次快照」能把原来的 DNS 找回来。

### 测试连通（IPv4 和 IPv6 都测）

点「测试连通」会在日志里打一份分段报告，两族各测三样：

```
---- 连通性测试 ----
· IPv4
    ping 网关 192.168.100.1              : 通
    ping DNS  192.168.100.1              : 通
    ping 223.5.5.5（阿里 DNS）     : 通（外网 IPv4 可达）
· IPv6
    本机全局地址：240e:37c:5111:7000::1003/128, ...
    ping 网关 fe80::4a81:d4ff:fec3:d487%9 : 通
    ping DNS  240e:37c:5111:7000::1      : 通
    ping 2400:3200::1（阿里 DNS）  : 通（外网 IPv6 可达）
```

几个细节：

- **IPv6 网关通常写成链路本地地址 + 区域号**（`fe80::...%9`），`.NET` 的 `Ping` 认这种写法，能直接 ping 通；
- **外网 IPv6 判据用 `2400:3200::1`（阿里公共 DNS 的 IPv6 地址）**，跟 IPv4 那边用的 `223.5.5.5` 是同一家，两边对照着看比较直观；
- 报告开头会**先打印本机的全局 IPv6 地址**。如果一个都没有，会直接提示「没有全局 IPv6 地址，下面多半不会通」，省得你看一堆「不通」还不知道为什么；
- 如果网卡的 **IPv6 协议被关了**（就是上面那个「关闭 IPv6」按钮），报告末尾会点出来，让你先开再测。

## 三条安全设计

**一、留空的字段一律不碰。**
只改你填了的东西。不想动 IPv6？IPv6 那栏空着就完事，程序碰都不会碰它。DNS 同理。

**二、动手之前先存快照。**
每次点「应用配置」或「一键恢复 DHCP」，都会先把这块网卡**当前**的完整配置（IPv4/IPv6 地址、网关、两族 DNS）存到

```
%APPDATA%\NetSwitcher\snap-<网卡索引>.txt
```

所以永远有退路 —— 点「还原上次快照」就能精确退回动手前的样子，比「恢复 DHCP」还准（因为原来的配置可能本来就是静态的）。

另外每次应用的值还会存一份 `last-<索引>.txt`，下次选中这块网卡时自动填回输入框。

**三、改完立刻回读校验。**
不信任 `netsh` 的退出码。命令跑完等 1.5 秒，重新读一遍网卡的真实状态，把 IPv4 / DNS4 / DNS6 都打出来给你看。日志里看到 `√ 目标 IPv4 已生效` 才算真的成了。

另外还有几道拦截：
- 掩码必须是连续的（`255.255.255.1` 这种直接拒绝）
- 地址最后一段是 0 或 255 会先问一句
- 网关不在同一子网会先警告（除非你就是要跨网段）
- 网关不能等于本机地址
- IPv4 的 DNS 栏填了 IPv6 地址（或反过来）直接拒绝

**注意：「一键开关 IPv6」不受快照保护** —— 它是网卡协议绑定，不是 IP 配置，不进快照。但它本身就是个开关，再点一次就回去了。

## 两组纵向对齐

IPv4 和 IPv6 两组的输入框放在**同一套列网格**上，两组用完全相同的列坐标，所以纵向完全对齐。

| 列 | 标签 x | 输入框 x | 宽 | 右边界 |
|---|---|---|---|---|
| 1 | 14 | 78 | 146 | 224 |
| 2 | 234 | 308 | 132 | 440 |
| 3 | 450 | 500 | 122 | 622 |

两组用的是**完全相同的列坐标**，所以 `地址` 上下对齐、`DNS 1` 上下对齐、`网关` 上下对齐。

**列宽不是拍脑袋定的，是按实测文字宽度算的**（用 `TextRenderer.MeasureText`，也就是 WinForms 自己排版用的同一个 API）：

| 列 | 该列最宽的内容 | 实测原始宽 | 文字区可用 | 余量 |
|---|---|---|---|---|
| 1 | IPv6 地址 `2001:4860:4860::8888` | 132 px | 140 px | 8 px |
| 2 | 掩码 `255.255.255.255` | 101 px | 109 px | 8 px |
| 3 | 预设 `Cloudflare` | 68 px | 99 px | 31 px |

第 2 列是下拉框，**右侧箭头要吃掉约 22px**，所以同样宽度下下拉框的文字区比文本框窄一大截 —— 这是第一版没对齐好时踩到的坑（`255.255.255.255` 被截成 `255.255.255`）。

第 3 列的标签从「常用 DNS」(70px) 缩成了「预设」(40px)，否则第三列挤不出下拉框所需的宽度。

**验证方式**（都是像素级，不是肉眼）：

1. **对齐**：四行（IPv4 行1/行2、IPv6 行1/行2）逐行扫描完整左边框，第 1/2/3 列分别是 `x=93 / 323 / 515`，**四行完全一致**；
2. **不遮挡**：每个框的左边框都是整列连续的 `#7A7A7A`（被标签压住的话中间会断）；
3. **不裁字**：把最长内容真的填进去再测墨迹宽度 —— 文本框右侧余量 20~51px，掩码下拉墨迹 91px（预期约 90px）且距箭头区还有 15px。

想看第 3 项的原始状态，跑：

```
NetSwitcher-chs.exe --demo
```

它会打开界面并把每个框都填成最长的典型内容，方便肉眼确认（只是排查排版用的，正常使用不会触发）。

## 全局字体

整个程序**只有一处**设置字体，在 `MainForm` 构造函数里：

```csharp
Font = new Font("Microsoft YaHei", 9f, FontStyle.Regular);
```

**所有子控件都是继承来的 —— 代码里只对菜单条显式设过一次 `Font`，理由见下。**

因为 WinForms 的 `Font` 属性会向上找父容器，子控件没自己设过就永远跟随。所以连 **ComboBox 的弹出列表也是同一个字体**（原生 ComboBox 画下拉项用的就是控件的 `Font` 属性）。

想换字体，改那一行就行，全界面一起变。**但如果你以后给某个控件单独写了 `Font = ...`，它就不再跟随全局了。**

### 唯一的例外：菜单条

```csharp
menu.Font = UiFont;      // BuildMenu() 里
```

这一行**是必须的**：`ToolStrip`/`MenuStrip` 的字体默认取 `SystemFonts.MenuFont`，中文系统上是 **`Microsoft YaHei UI`** —— 跟「微软雅黑」是两个不同的字体族，而且 `ToolStrip` 不跟随窗体的 `Font`。

不写这一行，菜单就成了整个界面里唯一字体不一致的控件。这是实测发现的：加完菜单跑 `--uidump`，46 个控件里 45 个是微软雅黑，只有 `MenuStrip` 是 `Microsoft YaHei UI`。

### 验证

```
NetSwitcher-chs.exe --uidump
```

遍历窗体上每个控件打印**实际生效**的字体，实测 **46 个控件全部 `微软雅黑 9pt`**，零例外。

## 命令行模式

```
NetSwitcher-chs.exe --list                 列出所有网卡和当前配置
NetSwitcher-chs.exe --selftest             列出网卡，并打印会执行的命令（不执行）
NetSwitcher-chs.exe --dns                  打印内置的常用 DNS 预设表
NetSwitcher-chs.exe --uidump               列出界面上每个控件的实际生效字体
NetSwitcher-chs.exe --about                直接弹出「关于」对话框
NetSwitcher-chs.exe --list -o D:\net.txt   顺便写成 UTF-8 文本文件
```

`--selftest` 会连 IPv6 DNS 命令和 IPv6 开关的 PowerShell 命令一起打出来，排错很方便。

## 两个已知的「假失败」

`netsh` 有些情况下明明是正常的，却返回退出码 1。程序里已经识别并忽略：

| 输出 | 意思 |
|---|---|
| `DHCP is already enabled on this interface.` | 本来就是 DHCP，不是错 |
| `delete address` 说地址不存在 | 清理残留地址时本来就没有，不是错 |

所以日志里偶尔看到 `OK` 后面跟着一句英文提示，是正常的。

## 实现备注

**IPv6 开关为什么走 PowerShell？**
`netsh` 没有开关协议绑定的能力，只能用 `Disable/Enable-NetAdapterBinding -ComponentID ms_tcpip6`。程序里用「接口索引」取网卡对象再管道过去：

```powershell
Get-NetAdapter -InterfaceIndex 9 | Disable-NetAdapterBinding -ComponentID ms_tcpip6
```

全程不出现中文网卡名，避开引号转义。**`-InputObject` 参数形式实测不能用**（类型不匹配），只有管道和 `-Name` 两种可行，选了管道。

需要 Windows 8 以上（有 NetAdapter 模块）。

**其余全部走 `netsh`**，并且用「接口索引」而不是接口名传参 —— 这样中文网卡名和引号转义都不是问题。

**一个 WinForms 布局坑（已修，改界面时注意）**

Label 的默认背景是不透明的 `SystemColors.Control` 灰，而 WinForms 里 `Controls.Add` 是**先加的 z 序更高**（在前）。

原来第一列的输入框放在 `x=58`，标签 `"DNS 1"` 比 `"地址"` 宽，它的自动尺寸右边界正好顶到输入框左边框上，把那 2px 竖线糊掉了——看起来就是「框的左边缺了一块」。同一列的 `"地址"` 字窄，留了余量，所以只有 DNS 那一行出问题。

修了两处：
1. 第一列输入框从 `x=58` 挪到 `x=76`，给标签留够宽度；
2. 所有 Label 背景改成 `Color.Transparent` —— 这样即使以后又撞上，也只盖住文字，不会糊掉别人的边框。

验证方式是**逐像素扫那一列**，看边框色 `#7A7A7A` 是不是整列连续（`--uidump` 查不出这种问题，它只管字体）。

**图标是怎么来的**

图标是**程序生成**的，不是手绘素材：

```
tools\make-icon.exe <原画.png> <输出目录>
```

原画用的是 DSH 鲸鱼余额插件里的 `DSniang1.png`（610×610、32bpp 带 Alpha 的干净角色特写）。生成器做的事：

1. 垫一层蓝色圆角方底（`#64B5F6 → #0D47A1`，跟界面主题同色）——
   之所以不直接用透明底原画：图标在任务栏只有 16~24px，透明底会缩成一小团蓝墨点
2. 把角色裁进圆角里铺满
3. **16/24/32px 用只框住脸的紧裁剪，48px 以上用完整原画** —— 原画细节太多，
   缩到 16px 就糊了，放大脸部至少还认得出是个人（iOS/安卓图标的常用手法）
4. 打包成 7 种尺寸的 `app.ico`（16/24/32/48/64/128/256，PNG 压缩条目）

**两个踩过的坑**：

- `Icon.ToBitmap()` 读 PNG 压缩的 32bpp 图标会渲染成**一片彩色雪花**。
  所以「关于」对话框里的大图是 `LoadAppPng()` 自己解析 ICO 目录、把那段 PNG 字节直接喂给 `Bitmap`，绕开 `ToBitmap()`。
- 编译时图标要嵌**两次**，各管一头：`/win32icon` 管资源管理器和任务栏，`/resource` 管窗体自己在运行时读。

改图标只要换原画重跑生成器，再重新编译即可。

## 自己重新编译

只需要 Windows 自带的 C# 编译器（任何 Win10/11 都有）：

```bat
cd /d E:\路由器\NetSwitcher
set CSC=C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe
set FLAGS=/nologo /target:winexe /platform:anycpu /codepage:65001 /win32manifest:app.manifest /win32icon:tools\app.ico /resource:tools\app.ico,NetSwitcher.app.ico /r:System.Windows.Forms.dll /r:System.Drawing.dll

:: 中文版
%CSC% %FLAGS% /out:NetSwitcher-chs.exe NetSwitcher.cs

:: 英文版（只多一个 /define:EN）
%CSC% %FLAGS% /define:EN /out:NetSwitcher-en.exe NetSwitcher.cs
```

**不需要**：.NET SDK、Visual Studio、NuGet、MSBuild、任何 DLL。

`/codepage:65001` 不能省 —— 源码是 UTF-8，不带这个参数编译器会按系统 ANSI 码页读，中文全乱。

代码用 **C# 5** 语法（不开 `/langversion`），因为 .NET Framework 自带的 csc 最高只认到 C# 5 —— 所以源码里没有字符串插值、没有 `?.`、没有表达式体成员。
